# BooksEngine

Рекомендации книг для себя и друзей — коллаборативная фильтрация на датасете Goodreads (UCSD).
Цель — список, по которому можно планировать чтение: как можно больше книг, которые человек оценит на 5.
Для постоянных читателей (2–3 книги в месяц): пока прочитано мало — проверенная «база» (мировая классика), чем больше
оценок — тем больше менее известного, что может понравиться. Читают по-русски (переводы).

## Модель

- `recommend` считает лучшей моделью — `models/layers` (шанс — `calibrate layers`): толпа «ценность» — `EASELike`
  (цель «оценка − 3», λ 500, вход — звёзды 1★…5★ с весами −1/−0.5/0.5/1/2) + ALS с весом 0.1; модель вкуса — вес 1.5.
  Веса звёзд выбраны по смыслу оценок (одна плохая книга не приговор жанру, 3★ — «прочёл, область интересна»):
  замер их не отличает от лучших; ночной подбор меняет только λ.
  Замысел «на старте классика, дальше менее известное» выполняется: медиана числа оценок книг списка — ~30 тыс.
  у людей с 20–49 оценками, ~25 тыс. у 50–199, ~16 тыс. у 200+ (колонка «известность» в `layers val`).
  Каждая выдача пишется в `profiles/history/`. Приложение (C#) пока считает старой смесью (`models/mix`).
- Правила списка (`filters.ListPicker`) — в выдаче и в замере: сборники не советуются, поздний том (#2 и дальше)
  неначатой серии заменяется первой книгой серии, книг одного автора — не больше одной на каждые 10 мест.
- Судья — качество списка на отложенных людях: средняя ценность книг топ-20, которые человек прочёл сам
  («угаданные»): 5★ = 2, 4★ = 1, 3★ = 0.5, 2★ = −0.5, 1★ = −1 (смысл оценок пользователя), сначала по человеку,
  потом по людям; порядок внутри двадцати не важен. Ограничение — угадано не меньше 90% от толпы «ценность» без
  вкуса (не от нынешней выдачи — иначе порог сползал бы с каждым прогоном); выбор упирается ровно в него. Прежние
  судьи печатаются рядом: «доля 5★ − доля 1–2★» приравнивала четвёрку к тройке и выбирает то же; сумма
  (оценка − 3) награждала «угадал, что и так прочтёт» — вкус при ней получал вес 0. Сравнение настроек — парное
  (разность на тех же людях): `ease-like-tune` и `layers val` меняют сохранённое, только если новое лучше по всему
  95% интервалу, — иначе выбор идёт по шуму.
  Группы активности (20–49, 50–199, 200+) — только для отбора людей в проверку поровну и для отчёта; судья — среднее
  по всем, модель под малый профиль не подгоняется: профиль постоянного читателя растёт. Тестовые люди в обучение не
  входят (fold-in).
- Профили пользователя и Леры — ориентир и поиск явных дефектов глазами (продолжения серий, дубли,
  похожее на оценённое низко), а не точечная настройка: `profile-check`, `layers profiles`, `why`.

## Команды

```bash
uv run pytest                                   # тесты (test_db_load — только с Postgres)
uv run booksengine prepare                      # очистка датасета (из кэша, --force — с нуля)
uv run booksengine split                        # отложенная выборка
uv run booksengine taste                        # модель вкуса → models/taste
uv run booksengine ease-like-tune [--weights … --force --min-user N]   # толпа «ценность» → models/ease_like
uv run booksengine layers val|test|profiles     # подбор и проверка толпа + вкус → models/layers
uv run booksengine profile-check                # каждая книга профиля прячется — её место
uv run booksengine why "<книга>"                # почему книга стоит на своём месте
uv run booksengine calibrate layers             # шанс «понравится» для models/layers
uv run booksengine recommend --ratings profiles/my_ratings.csv
scripts/night.sh                                # на ночь: весь подбор, тест, шанс, списки → reports/
uv run booksengine journal                      # что прочитано из советов и как оценено (profiles/history/)
```

Остальные команды и порядок сборки моделей — `README.md` («Команды») и `uv run booksengine --help`.

## Предметная область

- Рекомендации — на уровне произведения (work), не издания. Оценки 1–5; `rating = 0` («на полке») отброшен.
- CF-ядро — k-core: человек ≥ 20 оценок, книга ≥ 100; ~101K книг, 595K людей, 83.6M оценок. EASE видит 30 000 книг.
- Продолжения начатых серий не советуются и не считаются попаданием. `dnf` = 1★.

## Правила

- Лицензия датасета некоммерческая: `data/`, `reports/`, `models/` не коммитить.
- Тесты пишут только в `tmp_path`, пути по умолчанию в тестах не использовать.
- Данных и моделей у агента нет: обучение и замеры запускает пользователь на своём Mac (16 ГБ RAM, диск почти полон).
- Правила можно пересматривать, если мешают эксперименту, — сказать об этом явно.
- В коде, конфиге и документах не ссылаться на номера пунктов `TODO.md` и шаги планов: пункт закрывается и
  удаляется, ссылка повисает. Писать суть и причину; история — в git (в коммитах номера можно).
- Коммитить и пушить в рабочую ветку; в `main` — только по просьбе.
- Общение и документация — по-русски, коротко и простым языком.
- Один следующий шаг с причиной, а не список вариантов; доводить до результата, которым можно пользоваться.
  Остальные идеи — в `TODO.md`.
- Объяснять простым языком, коротко; большие таблицы — только когда нужны для решения.
