# BooksEngine

Рекомендации книг для себя и друзей — коллаборативная фильтрация на датасете Goodreads (UCSD). Цель — список, по
которому можно планировать чтение: как можно больше книг, которые человек оценит на 5.

## Чем руководствоваться

- Главное — не советовать мусор: потерять хорошую книгу лучше, чем показать пять, которые не зайдут. Правку, которая
  ловит пропущенные хорошие книги ценой риска плохих, принимать только с доказательством, что плохих не прибавилось.
- Читатели постоянные (2–6 книг в месяц), читают по-русски (переводы). Пока оценок мало — проверенная классика; чем
  больше оценок — тем больше менее известного, что может понравиться.
- Приложение (`dotnet/`, `web/`) сейчас не в фокусе.

## Как проверять изменение модели

- Судья — качество списка на отложенных людях; число угаданных книг — ограничение, а не цель.
- Варианты сравнивать парно (разность на тех же людях). Новое принимать, только если оно лучше по всему 95%
  интервалу, — иначе выбор идёт по шуму.
- Сырое качество вариантов с разным числом угаданных не сравнивать: у смелого списка фора. Сравнивать с контролем
  «шум вместо вкуса» при том же числе угаданных.
- Не подгонять модель под один этап пути читателя и под профили пользователя и Леры. Профили — чтобы глазами искать
  явные дефекты: продолжения серий, дубли, похожее на оценённое низко.
- Перед опытом прочитать итоги в `docs/model.md`, чтобы не повторять проверенное. Итог опыта, в том числе
  отрицательный, дописать туда.

## Самостоятельность

- Методику замера (судью, порог угаданного, контроли) выбирать самому и обосновывать цифрами. Пользователя
  спрашивать только о вкусе и продукте.
- Доводить до результата, которым можно пользоваться. В отчёте — один следующий шаг с причиной, а не список
  вариантов; остальные идеи — в `TODO.md`.
- Правила этого файла можно пересматривать, если мешают эксперименту, — сказать об этом явно.

## Правила

- Лицензия датасета некоммерческая: `data/`, `reports/`, `models/` не коммитить.
- Тесты пишут только в `tmp_path`, пути по умолчанию в тестах не использовать. Перед коммитом — `uv run pytest`.
- Обучение и замеры идут на Macbook M1 Pro пользователя (16 ГБ RAM). Если агент работает там же — данные и модели
  ему доступны: долгие прогоны — в фоне с логом в `reports/`, тяжёлые — по одному. Без данных (облачная сессия)
  прогоны запускает пользователь.
- В коде, конфиге и документах не ссылаться на номера пунктов `TODO.md` и шаги планов: пункт закрывается и удаляется,
  ссылка повисает. Писать суть и причину; история — в git (в коммитах номера можно).
- Этот файл — только о том, как работать. Устройство модели, настройки и итоги опытов — в `docs/model.md`, команды —
  в `README.md`, то, что видно из кода, — нигде.
- Коммитить и пушить в рабочую ветку; в `main` — только по просьбе.
- Общение, документация и комментарии — по-русски, коротко, простым языком; большие таблицы — только когда нужны
  для решения.
