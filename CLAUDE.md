# BooksEngine

Рекомендательная система книг для себя и друзей. Главная цель — точный и надёжный механизм
рекомендаций, по которому можно реально планировать чтение. UI/UX пока не важен.

Инструмент для узкого круга, не продукт для рынка: оптимизируем качество рекомендаций,
а не гибкость и масштаб. Пользователь и друзья читают только по-русски (переводы) и хотят
проверенную «базу», а не нишевые книги: «лучше быть уверенным, что книга стоит времени».

## Стек и структура

- **Python 3.12 (uv)** — только офлайн: очистка, обучение, метрики, загрузка каталога и
  векторов в БД. DuckDB + Parquet (zstd): 228M строк обрабатываются вне памяти.
- **C# / .NET** — онлайн: владелец схемы БД (EF Core-миграции) и ASP.NET API (`dotnet/BooksEngine.Api`):
  выдача смеси по модели из БД в памяти — повтор Python, сверяется эталонным тестом (`GoldenTests`).
- **Фронт** — React + TypeScript + Mantine (`web/`), типы API — из OpenAPI (`npm run gen:api`).
- **PostgreSQL + pgvector** — основная БД: каталог, пользователи приложения, векторы модели.
  Оценки датасета в БД **не грузятся** — обучение читает Parquet (решение пользователя).
- Подход — только коллаборативная фильтрация. Текстовые эмбеддинги отложены до появления
  новых источников данных (решение пользователя).

## Команды

```bash
uv run booksengine prepare          # staging → профиль → очистка → валидация → отчёт
uv run booksengine prepare --force  # пересобрать с нуля (~4 мин)
uv run booksengine validate         # инварианты по готовым data/clean/*.parquet
uv run booksengine report           # пересобрать отчёт без пересчёта
uv run pytest                       # test_db_load — против запущенного Postgres, иначе skip

docker compose up -d                                        # PostgreSQL + pgvector
(cd dotnet/BooksEngine.Db && dotnet ef database update)     # применить миграции
uv run booksengine load-db [--force]                        # каталог → БД; тот же manifest повторно не грузится
uv run booksengine split [--force]                    # отложенная выборка → data/model/split/
uv run booksengine evaluate <model> --stage val|test  # перебор настроек (модель сохраняется) / замер на тесте
uv run booksengine calibrate [model]                  # шанс «понравится» (по умолчанию mix) → models/<model>/chance.json
# смесь (mix) не обучается: после переобучения als_neg или ease — `evaluate mix --stage val`, затем `calibrate mix`
uv run booksengine report-3a                          # reports/stage3a_report.md
uv run booksengine ease-size                          # reports/ease_size.md — стоит ли расширять EASE (новые профили)
uv run booksengine taste                              # модель вкуса: перебор на валидации → models/taste, reports/taste_val.md (~1–1.5 ч)
uv run booksengine taste-gap                          # reports/taste_gap.md — личная точность моделей на валидации (п. 37)
uv run booksengine recommend --ratings profiles/my_ratings.csv [--top 20]  # рекомендации по CSV

# веб-интерфейс
uv run booksengine export-model                     # models/mix → БД для API (перезаписывает модель целиком, ~3 мин)
dotnet run --project dotnet/BooksEngine.Api         # API на :5080, модель грузится при старте (~16 с)
(cd dotnet && dotnet test --project BooksEngine.Api.Tests)  # запускать из dotnet/ (global.json: MTP); GoldenTests — C# = Python
(cd web && npm run dev)                             # фронт на :5173
(cd web && npm run gen:api)                         # типы TS из OpenAPI после изменения контрактов (API запущен)
# после переобучения смеси или load-db: export-model → POST /api/admin/reload-model (или перезапуск API) → dotnet test

# сравнить вариант очистки с текущим: сохранить ядро, поменять config, prepare --force, затем
uv run booksengine exp save <имя>   # data/clean → data/exp/<имя>/ (до пересборки)
uv run booksengine exp split        # общий тест всех ядер (data/exp/*/ + текущий data/clean как «new»)
uv run booksengine exp run          # популярность, ALS, kNN с фиксированными настройками → models/eval/exp/
uv run booksengine exp report       # reports/cleanup_experiment.md
```

Пути к датасету — `RAW_DIR` / `DATA_DIR` в `.env` (шаблон — `.env.example`).

## Окружение (машина пользователя, 2026-09-23)

- macOS, 16 ГБ RAM, 10 CPU. **Диск почти заполнен**: ~16 ГБ свободно (2026-09-23).
- Сырые файлы датасета — `~/Downloads` (список — `README.md`); `goodreads_books.json` распакован (9.2 ГБ).
  `data/` (staging + clean + profile.json) уже собран — `prepare` отработает из кэша.
- Системный Python 3.14 не подходит (нет колёс `implicit` и др.) — проект на 3.12 через uv.
- Docker; `psql` локально нет — `docker compose exec db psql -U booksengine`. .NET SDK 10.

## Предметная область

- **Издание (edition, `book_id`)** — конкретная публикация: перевод, переплёт, аудиокнига.
- **Произведение (work, `work_id`)** — все издания одного текста. **Оценки и рекомендации —
  на уровне произведения**; оценки нескольких изданий у пользователя сворачиваются в среднее.
- **Явная оценка** — rating 1–5 в Goodreads. `rating = 0` — не оценка, а «на полке» /
  «прочитано без оценки»: отбрасывается при очистке (решение 2026-09-23), исходные записи — в staging.
- **CF-ядро** — k-core (пользователь ≥ 20, произведение ≥ 100 оценок): `works.in_cf`, ~101K книг,
  595K пользователей, 83.6M оценок. Каталог (1.52M произведений) шире ядра — по нему
  сопоставляются книги новых пользователей.
- **Очистка оценок** до k-core: не-книги (`works.is_nonbook`: ноты, раскраски, календари,
  аудиокурсы — шаблоны названия + исключения в `config/cleaning.yaml`), слияние дублей,
  пользователи с sd < 0.2, с ≥ 90% одинаковых оценок и с > 3000 оценок.
- **Дубль произведения** — «тень» той же книги под другим `work_id`. Уверенные тени (то же
  название + основной автор, < 10% оценок главного) слиты в главное: `data/clean/work_merges.parquet`
  (тень → главное; нужно и для сопоставления CSV). Спорные (адаптации, пересказы) — фильтр выдачи (п. 11).
- **Серия** — из названия «Title (Series, #N)», бокс-сет «#1-7» — та же серия. Продолжения и части начатой
  серии не советуются и не считаются попаданием (решение пользователя: оценка серии — оценка всей серии);
  основная метрика стенда — вне начатых серий (`docs/resheniya.md`, «продолжения серий»).
- **Основной автор** — автор без `role` (не иллюстратор, не переводчик): `clean.primary_authors`.
- **Сборник** (`works.is_collection`) — box set / omnibus. Оценки остаются в матрице,
  при выдаче не рекомендовать сборник тому, кто оценил его части (решение 2026-09-23).
- **Шкала — только 1–5**, как у Goodreads: в профиле CSV (`rating`), в БД (`ratings.value`), в модели.
  1–10 не поддерживается (решение 2026-09-24): формулой не переводится. `dnf` = 1, но во входе EASE
  вес 0, а не −2 (`mix.DNF_INPUT`, п. 31): одна брошенная книга не должна топить всего автора.
- `original_title` у переводов — транслит оригинала («Prestuplenie i nakazanie»); основное
  название произведения берётся из лучшего издания.

## Рабочие ориентиры

- **Решения обосновываются данными.** Порог, правило, выбор модели — с цифрой из данных или
  офлайн-метрики, а не «по опыту». Цифры в отчёте подставляются из данных, не вписываются руками.
- **Судья модели — метрики ранжирования на отложенной выборке**, но выдачу смотреть глазами
  на живых профилях: метрика объясняет увиденное, а не заменяет его.
- **После любого изменения или калибровки модели — топ-20 на `profiles/my_ratings.csv`** (правило
  пользователя, 2026-09-23): показать пользователю рядом с прежней выдачей и оценить на адекватность
  (продолжения серий, части оценённых сборников, книги, похожие на оценённые низко). Без этого
  изменение не считается проверенным, какими бы ни были метрики. Было: метрика росла от продолжений
  серий, а выдача на профиле это сразу показывала.
- **Целевые пользователи — читающие: группы 50–199 и 200+ оценок.** 20–49 — вторична
  (`docs/resheniya.md`, «целевая группа»). Настройка модели выбирается по NDCG@20 всех пользователей
  (по группам не разделять — решение пользователя), а сравнение моделей и выводы — по целевым группам.
- **Воспроизводимость.** Всё пересобирается одной командой; два прогона `--force` дают
  одинаковые контрольные суммы в `manifest.json`. Агрегаты с плавающей точкой, которые
  сравниваются с порогом или экспортируются, округлять — иначе параллельные суммы дают
  разные биты от прогона к прогону (было 2026-09-23: пользователь на пороге sd 0.2 то
  попадал под фильтр, то нет).
- **Лицензия датасета — только некоммерческое использование.** Сырые данные и любые
  производные (parquet, отчёты с данными, модели) не коммитить: `data/`, `reports/`, `models/`
  в `.gitignore`.
- **Диск почти заполнен.** Промежуточные таблицы на сотни миллионов строк писать сжатым
  Parquet (`clean.SPILL_DIR`), а не держать в памяти / спилле DuckDB.
- **Ужесточать очистку только по метрикам модели, на одном и том же тестовом наборе.**
  Более жёсткий фильтр почти всегда улучшает офлайн-метрики сам по себе: из теста уходят
  трудные случаи (редкие книги, пользователи с малым числом оценок). Реальные рекомендации
  от этого не улучшаются, а каталог сужается. Инструмент — `booksengine exp`: общий тест для
  всех вариантов ядра.
- **Тесты пишут только в `tmp_path`.** Функции с путями по умолчанию (`evaluate.tune`, `test`)
  вызывать в тестах с явными `models_dir` / `eval_dir` — было 2026-09-23: тест затёр `models/popularity`.
- Метаданным Goodreads доверять выборочно: `media_type` размечен неверно («Dracula» — «not a
  book»), фильтровать по нему нельзя.

## Как работаем

- После каждого этапа — стоп, показать результат, ждать подтверждения.
- При неоднозначности — спрашивать, а не угадывать.
- Перед крупным изменением — план с аргументацией и способом перепроверки, затем ждём «поехали».
- Не вводить скрытый технический долг. Встретил баг, несогласованность или техдолг — либо
  чини на месте, либо сразу короткий пункт в `TODO.md`.
- Не запускать `git commit` или `git add`, пока пользователь явно не попросит.
- Документация и общение — на русском.
