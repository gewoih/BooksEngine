# Отложено

## 35. Модель в БД не знает, на каком каталоге выгружена

`load-db` с новым `manifest.json` обновляет каталог на месте; модель (`work_embeddings`, `work_exclusions`,
обложки) остаётся от прошлого экспорта. Удалённые книги уходят каскадом — API это видит (пропуск столбца →
модель не загружена, выдача 503), а смена `in_cf` и названий без удаления — нет: выдача молча считается по
старой модели, пока кто-то не вспомнит про `export-model` (правило есть только в CLAUDE.md). **Что сделать:**
`export-model` пишет в `model_meta` отпечаток загруженного каталога (последний `source_loads`), API при
загрузке сравнивает и при расхождении не грузит модель (503 с текстом «запустите export-model»).
Где: `export_model.write`, `ModelLoader.LoadAsync`.

## 36. «Alice in Wonderland» не отфильтрована при оценённой «Alice's Adventures in Wonderland & Through the Looking-Glass»

Профиль Леры (2026-09-24): оценена «Alice's Adventures in Wonderland & Through the Looking-Glass» (5★), а на 47-м
месте выдачи — «Alice in Wonderland» (Кэрролл) — та же книга. Фильтр «уже оценено» (`model/filters.py`) не ловит:
ключи названий разные («alice in» против «alice's adventures in»), а объединённое издание через «&» не считается
сборником (сборник — `is_collection` или « / » в названии). **Что сделать:** посмотреть, сколько в ядре пар «&»-изданий
с частями одного автора и сколько ложных («Pride & Prejudice» — не сборник): если «&» между двумя названиями
того же автора, которые сами есть в ядре, — считать сборником; варианты названия («Alice in Wonderland») — через
совпадение по ключевым словам внутри автора, проверить на числе ложных пар. Где: `filters.work_info`, `RatedFilter`,
пары в `export_model.exclusion_pairs`.

## 33. Школьная программа США тянет выдачу и объяснения

На эталонном профиле у «Повелителя мух», «Над пропастью во ржи», «Великого Гэтсби», «Убить пересмешника» одно и
то же «потому что: О мышах и людях, Скотный двор, 1984»; «Алая буква» ← «Гроздья гнева». Объяснение честное
(проверка удалением: без названных книг рекомендация выпадает из топ-20 в 86% случаев, `docs/resheniya.md`,
«объяснение выдачи»), но малоинформативное: книги связывает школьная программа США, а не содержание. Решение
пользователя (2026-09-24): пока оставить до профилей друзей.

**Профиль Леры (2026-09-24, модель 30K) — условие выполнено, и дело не только в объяснении.** Добавлены 6 давно
прочитанных книг из её топ-50; одна из них — «Повелитель мух» на 4★. После этого он в объяснениях 10 книг из 50,
почти всегда в связке «О мышах и людях, Повелитель мух…», а все 5 новых книг топ-20 — школьная программа:
«Скотный двор», «Гекльберри Финн», «1984», «Гамлет», «Одиссея»; «Ромео и Джульетта» — 23-я «потому что: О мышах и
людях, Повелитель мух, Франкенштейн». Одна четвёрка школьной книге сдвигает выдачу к программе, а не к вкусу.
**Что сделать:** (1) выдача — проверить на тесте снижение веса книг-«узлов» во входе EASE (книги, которые читают
«все со всеми», например по доле соседей с большим весом), по целевым группам и топ-20 обоих профилей;
(2) объяснение — называть книги с наибольшим вкладом относительно их среднего вклада по топу («характерные для
этой рекомендации»), заново проверить удалением (`model/explain.py`, `reason`).

## 20. Русские названия книг и имена авторов

Отложено 2026-09-23: демо без русских названий, «главное — работающий алгоритм» (решение пользователя).
Вместе с ним отложен фильтр выдачи «только книги с русским переводом».

**Проблема.** Русское название есть только через русские издания — у ~2% ядра (нет у «1984»,
«Властелина колец»); авторов на кириллице нет.

**Предложение (не утверждено).** Таблицы `work_titles(work_id, lang, title, source)` и
`author_names(...)`; источники: русские издания → Wikidata (свойство «Goodreads work ID», сначала замерить
покрытие) → LLM-перевод только для CF-ядра (`source = 'llm'`, издаются под своими названиями: «Pet
Sematary» — «Кладбище домашних животных»). Проверка: 36 книг профиля находятся по русскому названию.

## 28. Серии по справочнику Goodreads, а не по названию

Серия сейчас берётся из названия «Title (Series, #N)» (`model/series.py`): размечено 46K из 101K книг
ядра, поле `series` изданий — 56%, но без `goodreads_book_series.json` (не скачан) его id не группируются.
Не ловятся серии без «#N» в названии (манга «Vol. 6», комиксы); короткие имена серий («Oz», «Cat»)
могут склеить чужие серии. Не разбираются номера вида «(Twilight, #1-4, 3.5)», «(The Maze Runner #0.5, #1-3)»:
такие бокс-сеты ловит только фильтр сборников `recommend` (п. 11, замер 2026-09-24). **Что сделать:** если пользователь скачает справочник — группировать по нему,
сравнить разметку с названием на ядре.

# Техдолг

## 30. `booksengine exp` не меряет основную модель

Сравнение вариантов очистки (`model/experiment.py`, `FIXED`) гоняет популярность, ALS и kNN; основная модель
теперь смесь ALS + EASE (`models/mix`). **Что сделать:** при следующем сравнении ядер добавить EASE (λ = 500,
500 соседей, 30 000 книг; обучение ~190 с, пик памяти 11.8 ГБ — не параллельно) и смесь 50/50 в `FIXED` и `run_core`.

## 12. Кэш `profile.json` не зависит от кода профилирования

Ключ кэша — только отпечатки сырых файлов; правка `profile.py` без `--force` оставит старые метрики в
отчёте. **Что сделать:** добавить в ключ хэш `profile.py` (`pipeline.prepare`, `raw_fp`).

## 13. Цифры в тексте отчёта этапа 1 вписаны руками (частично)

Абзац о пороге k-core по книге считается из `kcore_options` (2026-09-23). Остальные литералы
`report.py` (например, «топ-аккаунт — 38 тыс. пятёрок», «~1% до 10–15%» в 4.4) — не проверены.
**Что сделать:** пройти `report.py`, числа — из profile / manifest.

## 15. Основной автор не выгружается

`clean.primary_authors` (автор без `role`) используется для поиска дублей, но в `work_authors.parquet` и
БД признака нет, а для объяснений («вам нравится этот автор») и сопоставления по автору нужен именно он
(у Гарри Поттера рядом с Rowling — иллюстратор). **Что сделать:** флаг `is_primary` в `work_authors`
(`pipeline.export`), колонка в БД (EF-миграция), `db_load`.

## 18. Связи произведения не знают своего источника

`load-db` считает все `work_authors` / `work_genres` своими и удаляет отсутствующие в parquet. Со вторым
источником перезагрузка Goodreads сотрёт чужие строки. **Что сделать:** при подключении второго
источника — `source_id` в таблицах связей (`db_load._replace_links`, `dotnet/BooksEngine.Db`).
