## 3b. Качество выдачи

## 8. Негативный сигнал: низкие оценки

**Проблема.** 1–2 балла — 8% оценок; ALS трактует любую оценку как «понравилось».

**Чем подтверждается** (тест 3a на ядре (20, 100), хэш-протокол п. 26, 2026-09-23). Low@20 (доля
скрытых 1–2★, попавших в топ-20): ALS — 11.3%, item-kNN (центрированные оценки) — 1.2%, популярность —
2.3%, при близком NDCG@20 (ALS 0.2735, kNN 0.2805).

**Что сделать.** Вариант ALS с оценкой относительно средней человека (двойка — отрицательный сигнал).
Цель: NDCG у пользователей 20–49 / 50–199 не хуже ALS, Low@20 — уровня kNN.

**Где.** `src/booksengine/model/als.py`, `evaluate.MODELS`.

---

## 23. Гибрид ALS + item-kNN

**Проблема.** Ни одна модель не лучше во всём (тест 3a на ядре (20, 100), хэш-протокол п. 26): ALS
сильнее на коротких профилях (NDCG@20 у 20–49 оценок 0.244 против 0.198), kNN — на длинных (200+: 0.383
против 0.307), почти не советует плохого (Low@20 1.2% против 11.3%), даёт объяснения «потому что вы
оценили X» и разнообразнее (coverage 0.20 против 0.03). На `profiles/my_ratings.csv` у части книг kNN нет
соседей среди прочитанного.

**Что сделать.** Сравнить: (а) ALS отбирает топ-200–500 кандидатов, kNN переранжирует и отсекает книги с
отрицательным вкладом; (б) взвешенная сумма нормированных баллов, вес зависит от числа оценок человека.
Критерии: NDCG у лёгких — не ниже ALS, Low@20 — уровня kNN. Делать после п. 8: если ALS научится учитывать
низкие оценки, гибрид может свестись к «ALS + объяснения kNN».

**Где.** `src/booksengine/model/` (модель по протоколу `Recommender`), `evaluate.MODELS`.

## 9. Разнонаправленный вкус

**Что сделать.** Кластеризация понравившихся пользователю произведений в пространстве item-векторов →
кандидаты из каждого кластера, чередование. Мерить точность и intra-list diversity против одного вектора
пользователя.

## 25. Порог выдачи: советовать только проверенные книги

**Проблема.** Пользователь хочет проверенную «базу», а не нишу (`docs/resheniya.md`, «очистка»). Порог
обучения уже 100 оценок; можно дополнительно советовать только книги с ≥ N оценок, не трогая обучение.

**Что сделать.** Маска кандидатов в выдаче (`metrics.top_k` — параметр `allowed`), N ∈ {100, 500, 1000}.
Для каждого N: NDCG@20, Low@20 и доля скрытых 5★, которые остаются доступны для совета; выдача на
`profiles/my_ratings.csv`. Падение NDCG от сужения — осознанная цена. Решение пользователя: «позже».

**Где.** `src/booksengine/model/metrics.py`, `evaluate.run_eval`, конфиг выдачи для 3c.

## 3c. Демо

Порядок: 19 (поиск, без него не сопоставить CSV) → 11.

## 11. Демо: оценки из CSV → рекомендации с объяснением

**Эталонный профиль.** `profiles/my_ratings.csv` — оценки пользователя (38 книг, 1–10, две `dnf`) с
закреплённым `goodreads_work_id`. «Recursion» (2019) и «Граф Аверин» (2021) новее датасета (2017).
Выдачу смотреть на нём глазами.

**Что сделать.** `booksengine recommend --ratings my.csv` (title / isbn / goodreads_id, rating 1–10).
Сопоставление с каталогом: ISBN → точно; иначе по названию + автору (правила — п. 19); тень из
`work_merges.parquet` → её главное произведение; несопоставленные — показать списком. Шкала 1–10 → 1–5.
Объяснение: «потому что вы высоко оценили X, Y» (соседи kNN) + общие жанры/авторы.
**Прогноз оценки («8.3 / 10») не показывать** (решение пользователя): прогноз kNN на эталонном профиле
ошибается на 1.35 балла — как «всегда ставить свою среднюю».
Фильтры выдачи:
- сборник (`is_collection`) — не советовать, если оценены его части;
- «X / Y» одного автора — тоже сборник: kNN советует «Animal Farm / 1984» при обеих оценённых;
- спорные дубли (п. 17) — не советовать произведение с тем же ключом «название + основной автор», что у
  оценённого, если номер в серии не отличается (адаптации, пересказы Oxford Bookworms / Classic Starts).

## 19. Ранжирование поиска по каталогу

**Проблема.** Сходство строки само по себе ранжирует плохо: «hary poter and the filosofers stone» —
настоящее произведение третье после «Harry Potter Books: …» и юбилейного издания; «Bulgakof» через `%`
не находит «Mikhail Bulgakov». В `authors` — дубли авторов Goodreads (два «Mikhail Bulgakov»), масштаб
не измерен.

**Что сделать.** `word_similarity` (`<%`) для частичного ввода, поиск по названиям всех изданий
(`editions.title`) со сворачиванием в произведение, порядок «точное название → автор → в CF-ядре →
популярность» (на `profiles/my_ratings.csv` это дало 36 верных из 36 найденных). Русские запросы
(«Гроздья гнева», «Мы») находятся только через `editions.title`. Межъязыковые дубли («Робинзон Крузо» —
отдельное произведение вне ядра) — при равном совпадении предпочитать произведение из ядра. Проверить на
списке запросов с ожидаемым ответом.

**Где.** Запрос — в API и в `recommend` (п. 11); индексы есть (`dotnet/BooksEngine.Db`).

# Отложено

## 20. Русские названия книг и имена авторов

Отложено 2026-09-23: демо без русских названий, «главное — работающий алгоритм» (решение пользователя).
Вместе с ним отложен фильтр выдачи «только книги с русским переводом».

**Проблема.** Русское название есть только через русские издания — у ~2% ядра (нет у «1984»,
«Властелина колец»); авторов на кириллице нет.

**Предложение (не утверждено).** Таблицы `work_titles(work_id, lang, title, source)` и
`author_names(...)`; источники: русские издания → Wikidata (свойство «Goodreads work ID», сначала замерить
покрытие) → LLM-перевод только для CF-ядра (`source = 'llm'`, издаются под своими названиями: «Pet
Sematary» — «Кладбище домашних животных»). Проверка: 36 книг профиля находятся по русскому названию.

## 21. Перебор настроек ALS не закончен

Проверены только 64 координаты (λ ∈ {0.01, 0.1}, α ∈ {1, 10}, валидация на ядре (10, 20)): λ не влияет,
α = 10 хуже по NDCG на 22%, зато вдвое разнообразнее — не нужно (известные книги в выдаче — не недостаток,
решение пользователя). **Что сделать:** 128 и 256 координат при λ = 0.1, α = 1 — когда ALS станет
кандидатом в победители или понадобятся её векторы (п. 9). `evaluate.MODELS["als"]`.

## 24. EASE^R: прогнать на реальных данных

Написан и покрыт тестами (`model/ease.py`), на реальных данных не запускался. **Что сделать:**
`evaluate ease --stage val` (λ ∈ {100, 500, 2000} × top-k ∈ {полная, 100, 500}, N = 20 000; 20–40 мин,
~5 ГБ памяти — не параллельно с kNN), затем `--stage test`. Выбор — по урезанной версии (в C# переносится
только она). Интересен как замена kNN в гибриде (п. 23).

# Техдолг

## 12. Кэш `profile.json` не зависит от кода профилирования

Ключ кэша — только отпечатки сырых файлов; правка `profile.py` без `--force` оставит старые метрики в
отчёте. **Что сделать:** добавить в ключ хэш `profile.py` (`pipeline.prepare`, `raw_fp`).

## 13. Цифры в тексте отчёта этапа 1 вписаны руками (частично)

Абзац о пороге k-core по книге считается из `kcore_options` (2026-09-23). Остальные литералы
`report.py` (например, «топ-аккаунт — 38 тыс. пятёрок», «~1% до 10–15%» в 4.4) — не проверены.
**Что сделать:** пройти `report.py`, числа — из profile / manifest.

## 15. Основной автор не выгружается

`clean.primary_authors` (автор без `role`) используется для поиска дублей, но в `work_authors.parquet` и
БД признака нет, а для объяснений («вам нравится этот автор») и сопоставления по автору нужен именно он
(у Гарри Поттера рядом с Rowling — иллюстратор). **Что сделать:** флаг `is_primary` в `work_authors`
(`pipeline.export`), колонка в БД (EF-миграция), `db_load`.

## 18. Связи произведения не знают своего источника

`load-db` считает все `work_authors` / `work_genres` своими и удаляет отсутствующие в parquet. Со вторым
источником перезагрузка Goodreads сотрёт чужие строки. **Что сделать:** при подключении второго
источника — `source_id` в таблицах связей (`db_load._replace_links`, `dotnet/BooksEngine.Db`).
