# Веб-интерфейс: библиотека, оценки, рекомендации — дизайн

Дата: 2026-09-24. Статус: согласован с пользователем, до плана реализации.
Параллельно идёт CLI-демо (TODO п. 11, `booksengine recommend`); его код выдачи — эталон для веба.

## Цель и рамки

Приложение для пользователя и пары друзей: оценить прочитанное → получить выдачу, по которой можно
планировать чтение. UI вторичен (ТЗ), но нужны основные страницы.

**Первая версия:**
- **Библиотека** — книги CF-ядра (`works.in_cf`, ~101K), весь каталог (1.52M) не нужен. Поиск,
  обложки, быстрая оценка.
- **Мои оценки** — сворачиваемая панель над библиотекой, свежие оценки появляются сразу.
- **Рекомендации** — топ 10 / 20 / 50 с шансом «понравится» и объяснением.
- **Карточка книги** — описание, жанры, похожие книги.
- **Импорт CSV** — кнопка в шапке; наш формат и экспорт Goodreads; **перезаписывает** оценки книг из файла.

**Не в первой версии:** полки («хочу прочитать», «читаю»), друзья, свободный список «название — автор»
при импорте, русские названия (п. 20), настоящая аутентификация, деплой на сервер.

**Развёртывание:** локально (`docker compose` + `dotnet run` + `vite`), но пользователь и сессия есть с
первого дня, чтобы потом выложить без переделки: сейчас «войти как» по cookie, позже — приглашение/пароль,
контроллеры не меняются (всё через `CurrentUser`).

## Архитектура

Соблюдается решение 2026-09-23 («архитектура»): Python — только офлайн, C# — онлайн.

```
Python (офлайн)                          C# (онлайн)                         Браузер
─────────────────                        ────────────────                     ─────────
обучение als_neg / ease / mix            BooksEngine.Api (ASP.NET Core)       React + TS + Mantine
      │                                   ├─ модель из БД в память            ├─ Библиотека (+ мои оценки)
booksengine export-model  ──► PostgreSQL ─┤  при старте / reload (~110 МБ)    ├─ Рекомендации
  (перезаписывает модель целиком)         ├─ /library, /works/{id}            ├─ Карточка книги (Drawer)
                                          ├─ /me/ratings, /me/import          └─ Импорт (кнопка в шапке)
                                          └─ /me/recommendations
                                                 ▲
                                                 │ эталонный тест: совпадение с Python
                                          golden_recommendations
```

- Всё «умное» (разбор серий, фильтры сборников и дублей, выбор обложки) остаётся в Python и попадает в
  C# **данными**, а не переписанным кодом. C# делает только линейную алгебру и SQL.
- Выдача считается на каждый запрос, без кэша и фоновых задач: fold-in 128×128 + сумма строк EASE — миллисекунды.
- Новые каталоги: `dotnet/BooksEngine.Api/` (зависит от `BooksEngine.Db`), `dotnet/BooksEngine.Api.Tests/`,
  `web/` (Vite), `src/booksengine/export_model.py`.

Отклонённые варианты: Python-сервис выдачи (FastAPI) за C# API — отменил бы «Python только офлайн», два
рантайма на сервере; фоновый пересчёт выдачи Python-воркером — задержка после оценки, очередь, сложнее.

## Выгрузка модели: `booksengine export-model`

Читает `models/mix` (+ его компоненты `als_neg`, `ease`, `chance.json`), `data/clean/*.parquet`,
вызывает функции `model/series.py`, `model/filters.py`, `model/explain.py` (не дублирует их) и пишет в БД
**одной транзакцией, перезаписывая всё** (решение пользователя: старые версии не хранить). Упал — в БД
остаётся прежняя модель целиком. Во время транзакции пик места ≈ 2× объёма модели (~1–2 ГБ).

Перед записью проверяет: отпечатки компонентов совпадают с `models/mix/params.json`, `chance.json`
откалиброван на этой смеси (`Chance.load(..., model_fp)`), `work_id` модели есть в `works` БД. Нарушение — исключение.

| таблица | содержимое | объём |
|---|---|---|
| `model_meta` | одна строка: отпечатки компонентов, `als_weight`, `ease_input`, `dnf_input` (`mix.DNF_INPUT`), ALS `alpha` / `regularization` / `neg_rule` / `neg_weight`, коэффициенты шанса (`coef`, `prior`, `p0`), пороги объяснения (`MAX_BECAUSE`, `MIN_OF_LEADER`, `DESPITE_OF_LEADER`), время экспорта | 1 |
| `work_embeddings` (есть) | вектор ALS 128 + `col` (столбец матрицы — для равных баллов) + `ease_pos` (позиция в 20 000 EASE или NULL); **колонка `model_version` удаляется миграцией** | 101K |
| `ease_weights` | `(from_pos, to_pos, weight)` по позициям EASE — 500 соседей на книгу | ~10M |
| `work_exclusions` | `(rated_work, excluded_work, reason)`: оценил X → не советовать Y. `series` — продолжение/часть начатой серии (`series.py`, убирает до расчёта шанса), `rated` — сборник ↔ часть, дубль (`filters.py`, убирает только из выдачи) | < 2M: замер 2026-09-24 — ≤ 1.8M проверок по авторам, 358K пар серий |
| `work_merges` | тень → главное произведение (сейчас в БД не грузится) | тысячи |
| `work_covers` | `work_id` → `image_url` самого популярного издания с обложкой (не `nophoto`) | 89K из 101K ядра |
| `golden_recommendations` | эталон: профиль → топ-50: место, `work_id`, балл, шанс, книги объяснения | ~200 |

Схемой владеет EF Core: таблицы и миграция — в `dotnet/BooksEngine.Db`, Python только пишет данные.

**Эталонные профили:** `profiles/my_ratings.csv` + 2–3 тестовых пользователя датасета из разных групп
(50–199, 200+). Выдача эталона — функцией `recommend` CLI-демо (п. 11), когда она готова.

**Обложки.** Ссылки Goodreads 2017 года живы (6 из 6 проверенных 2026-09-24). Обложка у лучшего издания —
65% ядра, у любого издания — 88% (89 078 из 101 154), поэтому берётся самое популярное издание с обложкой.
В URL размер: `…m/…` — сетка, `…l/…` — карточка. Без обложки — заглушка с названием. Копии к себе не
сохраняем (диск); Goodreads может закрыть ссылки — приемлемо.

## Расчёт выдачи в C# (`RecommendationService`)

Модель загружается в память при старте и по `POST /admin/reload-model` (сравнение отпечатка в `model_meta`).

1. Оценки человека → книги ядра (вне ядра — пропускаются, в интерфейсе помечены «не влияет»).
2. ALS fold-in, как `ALS.fold_in_system`: `m = alpha·r` (для `neg_rule` — `neg_weight`), `p = ±1`,
   `A = YᵀY + Yuᵀ·diag(m)·Yu + λI`, решение `A·x = Yuᵀ·((1 + m)·p)` Холецким (MathNet.Numerics).
   Балл — `x·Yᵀ` по 20 000 книг EASE.
3. EASE: `Σ v_i · B[i, ·]`, `v` — вес оценки (1★ −2 … 5★ +2), 3★ = 0.
4. z-нормировка каждого компонента по 20 000 книг, `w·z(ALS) + (1 − w)·z(EASE)`, `w = als_weight`.
5. Исключить оценённые книги и `work_exclusions` для оценённых.
6. Топ-N. **Шанс** — `Chance.predict`: место в личном рейтинге (`personal_pct`) + щедрость человека.
   **Объяснение** — вклады книг входа, как `explain.contributions` / `reason`: «потому что вы высоко
   оценили X, Y», «несмотря на Z».

Прогноз оценки («8.3 / 10») не показывается (решение пользователя, п. 11).

## API

Минимальные эндпоинты .NET 10, встроенный OpenAPI → `openapi-typescript` генерирует типы для фронта.
`/me/*` — пользователь из cookie.

| эндпоинт | что делает |
|---|---|
| `GET /users`, `POST /users`, `POST /session` | список, создание по имени, «войти как» |
| `GET /library?q=&page=` | книги ядра по 50: обложка, название, основной автор, год, число оценок, моя оценка. Без `q` — по популярности (`cf_ratings`); с `q` — поиск по рецепту из журнала решений («поиск по каталогу»): `word_similarity`, `editions.title` со сворачиванием в произведение, порядок «точное название → автор → популярность» |
| `GET /works/{id}` | карточка: описание, авторы, жанры, год, обложка `l`, моя оценка, мой шанс (если книга в EASE и не оценена), 10 похожих — соседи EASE с наибольшим весом |
| `PUT /me/ratings/{workId}` `{value: 1–5 \| "dnf"}`, `DELETE` | `dnf` = оценка 1 + `shelf_entries.status = dnf`; во входе EASE — вес `dnf_input` (0), в ALS — как 1★ |
| `GET /me/ratings` | последние сверху, с пометкой «вне ядра» |
| `POST /me/import` (multipart CSV) | формат по заголовку (см. ниже) → итог |
| `GET /me/recommendations?n=10\|20\|50` | топ-N: книга, шанс %, объяснение |
| `POST /admin/reload-model` | перечитать модель из БД |

### Импорт

- **Наш формат:** `goodreads_work_id,rating,status` (как `profiles/my_ratings.csv`); `status = dnf` → 1 (и вес `dnf_input` в EASE).
- **Экспорт Goodreads:** `Book Id` (издание) → `external_ids` → произведение; `My Rating = 0` — без оценки,
  пропускается; `Exclusive Shelf` — справочно.
- Произведение-тень → главное через `work_merges`.
- **Перезаписывает** оценки книг из файла; оценки, которых нет в файле, остаются (решение пользователя).
- Книга в каталоге, но не в ядре — сохраняется, помечена «не влияет»; нет в каталоге — «не найдено» списком.
- Ошибки по строкам (формат, оценка вне 1–5) — в отчёт, файл целиком не падает.
- Ответ: добавлено / обновлено / пропущено / не найдено (со строками).

## Фронтенд

React + TypeScript + Vite + **Mantine** (`Rating`, `Autocomplete`, `@mantine/dropzone`,
`@mantine/notifications`, `Drawer`), TanStack Query, React Router. Tailwind не используется (конфликт
базовых стилей с Mantine).

- **Шапка:** пользователь («войти как»), «Импорт» (модальное окно с drop-зоной и итогом), ссылки на страницы.
- **Библиотека:** поиск, список с обложками, страницы по 50. Звёзды 1–5 при наведении (на узком экране —
  всегда) + кнопка «бросил». Над списком — сворачиваемая панель «Мои оценки»: оптимистичное обновление,
  правка и удаление.
- **Рекомендации:** 10 / 20 / 50; обложка, название, автор, шанс %, объяснение, звёзды. Оценённая здесь
  книга пропадает, выдача перезапрашивается (инвалидация запроса).
- **Карточка:** `Drawer` по клику на книгу с любой страницы.

## Ошибки и крайние случаи

- Нет оценок в ядре — подсказка «оцените книги или импортируйте CSV»; порога «минимум N оценок» нет
  (не обосновать данными).
- Модель не выгружена — рекомендации и шанс отвечают `503` с текстом; библиотека и оценки работают.
- Модель в памяти не совпадает с `model_meta` после экспорта — выдача продолжает работать на старой до reload.

## Проверка

- **Эталонный тест (xUnit):** на `golden_recommendations` — тот же топ-N в том же порядке, балл и шанс
  совпадают до 1e-4, объяснение называет те же книги. После каждого экспорта модели — `dotnet test`.
- **Импорт:** два маленьких CSV (наш и Goodreads), включая тень, издание вне ядра, неизвестный id, `0`.
- **API:** на тестовой БД; без запущенного Postgres — skip (как `test_db_load`).
- **Python:** pytest на `export-model` на синтетической мини-модели, запись только в `tmp_path` / тестовую БД.
- **Фронт:** без автотестов в первой версии; `tsc` + `vite build`. Ручная проверка в браузере: библиотека,
  оценка, импорт `profiles/my_ratings.csv`, топ-20 рекомендаций рядом с выдачей CLI — по правилу проекта
  «топ-20 на эталонном профиле».
