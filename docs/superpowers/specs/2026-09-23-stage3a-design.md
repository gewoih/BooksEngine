## 1. Цель

Честно сравнить baseline по популярности и три CF-модели в том режиме, в котором будут работать
реальные пользователи приложения: **новый человек, которого нет в обучении, рекомендации считаются
по его оценкам без переобучения (fold-in)**. Выбрать модель для 3b/3c по метрикам ранжирования,
отдельно глядя на «лёгких» пользователей (10–49 оценок) — это профиль пользователя и его друзей.

Результат — отчёт `reports/stage3a_report.md` с таблицей «модель × метрика × группа активности»,
цифры подставляются из данных.

**Вне 3a:** загрузка векторов/соседей в БД; правило сборников при выдаче; сопоставление CSV; сравнение
способов учёта низких оценок (3b, п. 8); кластеры вкуса (3b, п. 9); вариант k-core (10, 10) (3b, п. 10).

## 2. Данные

Вход — `data/clean/ratings.parquet` (CF-ядро (10, 20): 95.5M оценок, 683 045 пользователей,
322 448 произведений; `rating` — float 1–5, у пользователя с несколькими изданиями — среднее) и
`data/clean/users.parquet` (`n_ratings`). Распределение оценок: 1–2★ — 8%, 3★ — 22%, 4★ — 36%, 5★ — 34%.

Работа с нецелыми оценками (среднее по изданиям, 0.3% строк): для метрик оценка округляется
«половина вверх» (3.5 → 4, 4.5 → 5, 2.5 → 3). В модели идёт исходное значение.

## 3. Сплит (п. 4) — `src/booksengine/model/split.py`

- Генератор `numpy.random.default_rng(seed)`, seed = 20260923, по отсортированному списку `user_id`.
- Две непересекающиеся случайные группы пользователей: **валидация — 5 000**, **тест — 20 000**.
  Обе **полностью исключены из обучения**.
- У каждого пользователя групп скрыто `max(1, round(0.2 · n))` случайных оценок; остальные — **вход**
  (профиль для fold-in).
- Группы активности (по полному числу оценок пользователя): 10–19, 20–49, 50–199, 200+.
  Выборка пропорциональная; в тесте ожидается ~1 800 человек в группе 10–19.
- Обучающая матрица — все оценки, кроме пользователей валидации и теста. Произведение, у которого в
  обучении не осталось оценок, остаётся в списке кандидатов; CF не может его поднять, скрытое попадание
  на нём засчитывается как промах (честно).
- Хранение: `data/model/split/{train_users,val_input,val_hidden,test_input,test_hidden}.parquet` +
  `split.json` (seed, размеры, отпечаток = checksum `ratings` из `manifest.json` + параметры сплита).
  При совпадении отпечатка сплит не пересобирается; `--force` — пересобрать.

## 4. Метрики (п. 5) — `src/booksengine/model/metrics.py`

Для каждого пользователя модель выдаёт топ-K (K = 20) из всех 322 448 произведений ядра, **исключая
произведения из его входа**.

Выигрыш скрытой книги (решение пользователя, вариант B): 5★ → 2, 4★ → 1, ≤ 3★ → 0 (после округления).

| метрика | определение | направление |
|---|---|---|
| **NDCG@20** (главная), NDCG@10 | DCG = Σ gain_i / log2(i+1) по позициям топа; нормировка на идеальный DCG из скрытых книг пользователя | ↑ |
| Recall@20 | доля скрытых 4–5★ в топе; знаменатель `min(число скрытых 4–5★, 20)` | ↑ |
| MAP@20 | средняя точность по бинарной релевантности 4–5★, та же нормировка | ↑ |
| Coverage@20 | число разных произведений во всех топах теста / 322 448 | ↑ (защита от «всем одни бестселлеры») |
| Low@20 | доля скрытых 1–2★, попавших в топ-20, среди пользователей, у которых они есть | ↓ (в 3a наблюдается, работа — 3b) |

Пользователи без скрытых 4–5★ не участвуют в NDCG/Recall/MAP; их число пишется в отчёт.
Все метрики — по всему тесту и отдельно по группам активности. Среднее по пользователям, с 95%
доверительным интервалом (бутстреп по пользователям, 1 000 повторов) — чтобы «модели почти равны»
было видно из отчёта, а не на глаз.

## 5. Модели (пп. 6–7) — `src/booksengine/model/`

Общий интерфейс (`base.py`):

```python
class Recommender(Protocol):
    name: str
    def fit(self, train: RatingMatrix) -> None: ...          # обучение на толпе
    def save(self, path: Path) -> None: ...
    @classmethod
    def load(cls, path: Path) -> "Recommender": ...
    def score(self, inputs: csr_matrix) -> np.ndarray: ...   # fold-in: оценки новых людей → баллы всех книг
```

`score` использует только сохранённые артефакты модели и входные оценки — ту же линейную алгебру
повторит C#-API. `RatingMatrix` (`matrix.py`) — CSR пользователь × произведение и отображения
`work_id` ↔ столбец, `user_id` ↔ строка.

**Популярность** (`popularity.py`). Байесовское среднее `(Σr + m·μ) / (n + m)` (μ — глобальное
среднее, m — сила сглаживания). Варианты на валидации: число оценок; байесовское среднее;
байесовское среднее × log(1 + n). Одинаковый список всем, минус вход.

**item-kNN** (`knn.py`).
- Оценки центрируются по средней пользователя (r − μ_u); вклад пользователя в похожесть взвешивается
  `1 / log(1 + n_u)` — понижение веса активных (решение этапа 1).
- Похожесть — косинус центрированных векторов книг с усадкой `n_common / (n_common + β)`.
- Хранится top-k соседей на книгу по модулю похожести, со знаком (отрицательная похожесть — тоже сигнал).
- Выдача: `score_i = Σ_j s_ij · (r_uj − μ_u)` по книгам входа j; вариант с нормировкой на Σ|s_ij|
  проверяется на валидации.
- Расчёт похожестей — блоками по столбцам (плотный блок ≤ 2 ГБ), 42 млрд пар «книга–книга» от
  общих пользователей; время фиксируется в отчёте.

**EASE^R** (`ease.py`).
- Только top-N произведений по числу оценок в обучении, N = 20 000 (у 13 390 книг ядра ≥ 1 000 оценок).
  Остальные книги получают балл −∞ (EASE их не рекомендует).
- B = I − P · diag(1/diag(P)), P = (XᵀX + λI)⁻¹, X — бинарная матрица «оценил» (стандарт модели;
  учёт оценки — в 3b).
- Для C# веса урезаются до top-k на столбец; в отчёт идут **обе** версии — полная и урезанная,
  выбор модели — по урезанной (её увидит пользователь).
- Полная B (1.6 ГБ float32) на диск не пишется.

**ALS** (`als.py`, библиотека `implicit`).
- Confidence `c = 1 + α · r` (выше оценка — выше уверенность).
- Fold-in: `x_u = (YᵀY + Yᵀ(C_u − I)Y + λI)⁻¹ YᵀC_u p_u` — решение линейной системы размера f × f
  по векторам книг Y; реализуется своим кодом на numpy (не через `implicit`), чтобы формула была явной
  для переноса в C#.
- Выдача: `score = Y · x_u`.

**Перебор настроек на валидации** (небольшая сетка, результат перебора — в отчёт):

| модель | параметры |
|---|---|
| популярность | вариант формулы; m ∈ {10, 100, 1000} |
| item-kNN | k ∈ {50, 100, 200}; β ∈ {0, 50}; нормировка да/нет |
| EASE^R | λ ∈ {100, 500, 2000}; top-k урезания ∈ {100, 500} |
| ALS | f ∈ {64, 128, 256}; λ ∈ {0.01, 0.1}; α ∈ {1, 10}; 15 итераций |

Лучшая комбинация каждой модели один раз меряется на тесте.

## 6. Выбор модели

Победитель — лучшая по NDCG@20 на тесте при двух условиях: обыгрывает популярность в целом и в
группах 10–19 и 20–49. Если доверительные интервалы NDCG@20 двух моделей пересекаются — они считаются
равными, и выбирается та, что проще переносится в C# и даёт прямое объяснение («потому что вы оценили
X, Y»). Итоговое решение принимает пользователь по отчёту.

## 7. Команды и артефакты

```bash
uv run booksengine split [--force]          # сплит → data/model/split/
uv run booksengine train <model> [--params] # обучение → models/<model>/
uv run booksengine evaluate [--stage val|test] [--model ...]  # метрики → models/eval/*.json
uv run booksengine report-3a                # reports/stage3a_report.md из models/eval/*.json
```

- Артефакты: `models/` (в `.gitignore`). Ожидаемый объём: kNN ~0.3 ГБ, ALS ~0.2 ГБ, урезанный EASE —
  сотни МБ.
- Выдача считается пачками пользователей (≤ 500 × 322K float32 ≈ 0.65 ГБ) — укладывается в 16 ГБ RAM.
- Новые зависимости: `scipy`, `implicit`, `numpy` (явно).

## 8. Тесты (`tests/`, синтетика)

- Сплит: тестовые и валидационные пользователи не в обучении; вход и скрытое не пересекаются и в сумме
  дают все оценки; размеры по формуле; тот же seed → тот же сплит.
- Метрики: NDCG/Recall/MAP/Coverage/Low на примерах, посчитанных руками; вход исключён из топа.
- Популярность: сглаживание на примере с 3 пятёрками против 1000 четвёрок.
- kNN: похожести и выдача совпадают с расчётом «в лоб» на матрице 6 × 5; блочный расчёт = цельный.
- EASE: B совпадает с формулой на малой матрице, диагональ B нулевая.
- ALS: fold-in пользователя из обучения совпадает (до допуска) с `implicit.recalculate_user`.
- Все модели: `save` → `load` → та же выдача.
