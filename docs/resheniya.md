## 2026-09-23 — этап 3: протокол оценки моделей

| вопрос | решение | почему |
|---|---|---|
| Как разбит этап 3 | подэтапы **3a** (стенд + модели, пп. 4–7) → **3b** (низкие оценки, разнонаправленный вкус, k-core, пп. 8–10) → **3c** (поиск, русские названия, демо, пп. 19, 20, 11) | этап слишком велик для одной спецификации; 3b и 3c меряются на стенде 3a |
| Тестовые пользователи — в обучении или нет | **исключены из обучения целиком**: 80% их оценок — вход fold-in, 20% скрыты для проверки | реальные пользователи приложения (пользователь и пара друзей) — новые люди, которых нет в обучении; их выдача считается fold-in без переобучения. Мерим этот же путь, иначе метрика завышена. Пользователи Goodreads — «толпа» для обучения и «дублёры» для проверки, не аудитория |
| Что считается попаданием | **градуированно**: скрытая 5★ — выигрыш 2, 4★ — 1, ≤ 3★ — 0; главная метрика — NDCG | 4–5★ — 70% оценок ядра, бинарный порог ≥ 4 не отличает «обожаю» от «сойдёт»; для планирования чтения важно первое. Относительный порог (выше личной средней) отвергнут: у щедрых пользователей почти не остаётся попаданий |
| Дубли произведений (п. 17): сливать при очистке или фильтровать при выдаче | **фильтр при выдаче** (вариант б): не советовать произведение с тем же ключом «название + основной автор», что у оценённого, если номер в серии не отличается; делается в демо (3c) | замер: 615 теней, 70K оценок — 0.07% ядра, на модель не влияет; эвристика шумная (262 ложных совпадения по номерам серии), слияние по ней испортило бы данные. Дефект виден только в выдаче |
| Выдача ALS на `profiles/my_ratings.csv` (64 координаты, α = 1): Сэлинджер, Фицджеральд, Голдинг, Хаксли, Камю, Кафка, «Преступление и наказание»… | **оценена пользователем положительно**: «многие книги знаю, слышал или планирую прочесть». Известные, «на слуху» книги в выдаче — **не недостаток** | поправка пользователя к анализу агента: 1/10 у «Белых ночей» — «не люблю любовные драмы без сюжета», а не «не люблю Достоевского»; «Преступление и наказание» он сам собирается читать. Низкая оценка — сигнал о книге, не об авторе; разнообразие ценой «известности» (α = 10, п. 21) не нужно |

## 2026-09-23 — этап 2: что и как лежит в PostgreSQL

| вопрос | решение | почему |
|---|---|---|
| Оценки датасета (95M) — в БД? | **не грузить**; обучение читает `data/clean/*.parquet`. Пользователей датасета (683K) — тоже нет | решение пользователя: «сейчас это вообще не нужно». Модель учится из Parquet, API будет работать по готовым векторам/похожестям; «голос толпы» попадает в БД результатом обучения (`work_embeddings`), а не сырыми строками. Экономия ~7 ГБ на почти полном диске |
| Каталог — целиком или только CF-ядро | **целиком** (1.52M произведений, 2.36M изданий) | пользователи ищут и оценивают любые книги, не только 322K ядра; по каталогу же сопоставляется CSV на этапе 3 |
| Поиск по библиотеке | `pg_trgm`, GIN-индексы по `works.title`, `works.original_title`, `editions.title`, `authors.name` | замечание пользователя: по библиотеке будут искать; триграммы находят при опечатках и неполном вводе |
| Оценки приложения | отдельная `ratings(user_id, work_id, value 1–10, scale_max)` только для `app_users` | с датасетом не пересекается, перезагрузка каталога её не трогает |
| Полки | одна таблица `shelves(user_id, work_id, status)`, статус ∈ to_read / reading / read / dnf | статусы книги у человека взаимоисключающие; пользовательских полок в ТЗ нет (вместо `shelves` + `shelf_items` из плана) |
| Goodreads-id | не ключ каталога: `external_ids(source, entity_type, external_id → internal_id)`; внутренние id выдаются в порядке Goodreads-id | новые источники; одинаковая раскладка id на пустой БД |
| Каталог пропал из новой версии данных, а на него есть оценки/полки приложения | загрузка **падает** (FK `ON DELETE RESTRICT`), БД не меняется | оценки пользователей не теряются молча |
| Автор без имени (2), издание без названия (3) | `authors.name`, `editions.title` — nullable | так в источнике; на этих авторов ссылаются произведения, у изданий есть ISBN. Не выдумываем значения |
| `works.media_type`, `best_edition_title`, `books_count` | не переносятся | `media_type` размечен неверно; `best_edition_title` всегда равен `title`; `books_count` считается по `editions` |

## 2026-09-23 — итоги этапа 1 (ответы на вопросы отчёта)

| вопрос | решение | почему |
|---|---|---|
| Сборники / box sets (10.3K произв., 0.8% оценок) | **оставить в матрице**, флаг `works.is_collection`; при выдаче не рекомендовать сборник тому, кто оценил его части | оценка сборника — настоящий сигнал вкуса («LOTR #1-3» у многих и есть «Властелин колец») |
| Сверхактивные, порог > 3000 оценок | **оставить** | за p99.9 (2 460); доля редких книг у них 11–32% против 1–2% — каталогизация; −1.7% оценок. Понижение веса активных пользователей всё равно делается в моделях этапа 3 (нормализация вклада пользователя в похожесть) — для всех, не только для этих 416 |
| Порог разброса sd < 0.2 (поднять до 0.3?) | **оставить 0.2** | в [0.2; 0.3) — «20 пятёрок и 1–2 четвёрки»: живые люди, слабый, но ненулевой сигнал; центрированные модели сами почти обнулят их вклад, а удаление стоит 0.56M оценок. При sd = 0 информации нет вовсе |
| k-core (10, 20) | **оставить**, проверить метрикой на этапе 3 (`TODO.md` п. 10) | ≥ 10 у пользователя: при holdout 20% остаётся 8 в профиле и 2 на проверку. ≥ 20 у произведения: порог 10 добавил бы 176K произв. при 2.5% оценок с ненадёжной похожестью, 50 — урезал бы ядро вдвое |
| Язык (каталог почти целиком англоязычный) | **пока приемлемо** | русская классика есть как переводы («Master and Margarita» — 15K оценок) |

## 2026-09-23 — архитектура

- **Python — только офлайн** (очистка, обучение, метрики, загрузка каталога и векторов в БД,
  демо этапа 3 как CLI). **C# — онлайн**: схема БД через EF Core-миграции (`dotnet/BooksEngine.Db`),
  позже ASP.NET API с fold-in по готовым векторам. Пользователь сначала спрашивал «может сразу C#?»;
  довод за Python — ML-библиотеки (`implicit`, `scipy.sparse`) и один код для очистки и обучения.
- **Только коллаборативная фильтрация.** Текстовые эмбеддинги описаний как кандидат/гибрид
  предлагались — пользователь отказался: «только CF по ТЗ». Вернуться, когда появятся новые
  источники без истории оценок (холодный старт).
- **`goodreads_interactions.csv`, а не `goodreads_interactions_dedup.json.gz`**: dedup-версия
  (11 ГБ) несёт даты и рецензии, но не помещалась на диск. Следствие — дат нет, временной сплит
  невозможен, holdout per-user.
