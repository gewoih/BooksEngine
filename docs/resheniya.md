## 2026-09-23 — гибрид ALS + item-kNN (п. 23): отклонён, основная модель — ALS

Идея: ALS лучше угадывает новые книги, kNN почти не советует плохого (тест, NDCG@20 / Low@20 всех:
0.192 / 9.0% против 0.145 / 2.3%) — взять порядок ALS и отсеять книги по kNN.

| вариант | решение | почему |
|---|---|---|
| Смесь баллов ALS и kNN (вес ALS n₀/(n₀ + n)), переранжирование топа ALS по kNN | **отклонены без замера** | прототип на эталонном профиле (ALS 128, kNN k = 3, β = 50, пул — топ-300 ALS): смесь при n₀ = 50 — четыре Кинга в топ-20 за две четвёрки (на ALS 64 было два), переранжирование — Кинг и бестселлеры. Пул 100 вместо 300 выдачу почти не меняет. Перекос к автору и бестселлерам противоречит цели пользователя (проверенная классика) |
| Вето: книга с отрицательным вкладом kNN (похожа на оценённые ниже своей средней) уходит в конец выдачи ALS | **отклонено** | валидация: NDCG@20 0.189 → 0.170 (50–199: 0.187 → 0.167, 200+: 0.196 → 0.182), Low@20 9.6% → 7.3%. Тот же размен уже даёт сам ALS (негативный сигнал β = 10: 0.171 / 7.1%), отклонённый в п. 8 как слишком дорогой. Из скрытых книг, выброшенных вето из топ-20 ALS, 67% человек оценил на 4–5★ и 8% на 1–2★: «ниже своей средней» ≠ «не понравилось» (та же причина, что у центрирования в п. 8) |
| Строгое вето: только книги — соседи kNN оценённых на 1–2★ | **не берём** | валидация: 0.187 / 8.4% — выигрыш по Low@20 на грани шума; на эталонном профиле топ-20 совпал с ALS, из топ-50 ушёл только «Том Сойер» |

Итог: **основная модель — ALS** (`models/als_neg`: 128 координат, «≤ 2», β = 0). kNN остаётся для объяснений
«потому что вы высоко оценили X» (п. 11) и шанса «понравится» (п. 29). Код гибрида удалён (не используется);
замер вето — `models/eval/p23_veto/`. Решение пользователя: «оставляем ALS».

256 — 0.62, kNN — 0.63 (п. 29 в `TODO.md`).

## 2026-09-23 — продолжения серий: не советовать и не считать попаданием

| вопрос | решение | почему |
|---|---|---|
| Советовать ли продолжения начатых серий | **нет, никогда** — ни в выдаче, ни отдельным списком | решение пользователя: «когда я ставлю оценку Гарри Поттеру, я ставлю оценку всей серии»; что у серии есть продолжение, человек знает без модели |
| Как мерить модели | **основная метрика — вне начатых серий**: продолжения серий из входа вычеркнуты и из кандидатов, и из скрытых книг (`model/series.py`, `evaluate.load_eval_holdout`); тот же фильтр — в выдаче | на валидации 75% попаданий kNN и 52% ALS были продолжениями серий, 45% топ-20 kNN — они же. Метрика мерила «угадай следующий том», и по ней kNN выглядел лучшей моделью; вне серий ALS находит новые книги точнее (NDCG@20 50–199: 0.172 против 0.132). Старые цифры — `models/eval/with_series/` |
| Как определять серию | **по названию «Title (Series, #N)»**, включая бокс-сеты «#1-7» и несколько серий через «;» | поле `series` изданий без справочника (`goodreads_book_series.json` не скачан) не группирует: у каждой книги «Гарри Поттера» свой id. Название размечает 46K из 101K книг ядра; поле изданий — 56%, разница в основном манга и комиксы |

## 2026-09-23 — целевая группа пользователей

заметного, но не цель). Слова пользователя: группу 20–49 «нельзя назвать читающей»; у него ~50 прочитанных
за пару лет, у постоянно читающих друзей — 100–200+. Критерий п. 8 «NDCG у 20–49 не хуже ALS» задним числом
не главный. *(Отменено 2026-09-23: вывод «в целевых группах kNN почти лучший» — 50–199: 0.260 против 0.270,
200+: 0.383 против 0.313 — сделан по метрике с продолжениями серий; вне серий ALS точнее в 50–199, см.

## 2026-09-23 — негативный сигнал в ALS (п. 8) и шкала эталонного профиля

| вопрос | решение | почему |
|---|---|---|
| Центрировать оценки по средней человека (`p = sign(r − μ_u)`, уверенность от \|r − μ_u\|, и в обучении, и на fold-in) | **отклонено** | тест: NDCG@20 0.2735 → 0.2035 (20–49: 0.244 → 0.155), Low@20 11.3% → 3.3%. «Ниже своей средней» ≠ «не понравилось»: отрицательными стали 41% четвёрок (12.5M релевантных оценок), у 83% четвёрок вес почти нулевой; в обучении единицы получили самый большой вес «понравилось» (`implicit` всегда p = 1). Замеры — `models/eval/p8_centered/` |
| Каким делать негативный сигнал | **только явно низкие оценки** (≤ 2 или ≤ μ_u − 1.5) → p = −1 с отдельным весом β, на fold-in; обучение item-факторов не трогать | сохраняет «человек читает такое» для 3–5★; настройка выдачи — одно обучение на весь перебор |
| Правило «ниже своей средней на 1.5» | **убрано** (2026-09-23) | порог 1.5 выбран агентом на глаз, не из данных; на метрике вне серий выиграл у «≤ 2» на 0.0006 NDCG — шум (интервал ±0.005); на краях странный смысл: при средней 3.0 двойка — «понравилось», при 4.6 тройка — «не понравилось». Пользователь: «зафиксируем ≤ 2» |
| Итог п. 8 | **`le2`, β = 0** — рабочая настройка ALS (`models/als_neg`); п. 8 закрыт, Low@20 уровня kNN — в гибрид (п. 23) | выбор по NDCG на валидации; тест: NDCG@20 0.2735 → 0.2760, Low@20 11.3% → 8.9%, ни одна группа не хуже. Больший β режет Low@20 ценой NDCG (β = 10: 5.8%, −6%) — до kNN (1.2%) не дотягивает. «μ − 1.5» везде чуть хуже «≤ 2». Выдача на эталонном профиле: верх не меняется, уходят книги, похожие на оценённые низко («Сто лет одиночества», «Лолита», «Том Сойер») |
| Шкала эталонного профиля | **своя пятибалльная** `rating5`, поставлена пользователем заново; 10-балльная оставлена рядом | 5/10 у пользователя — то 2/5, то 3/5: формулой не переводится. Старое `rating / 2` давало 1/10 → 0.5, вне шкалы |
| Недочитанные (`dnf`) | **= 1/5** | решение пользователя |
| «Гарри Поттер» | **одна строка — бокс-сет #1–7** | пользователь оценивает серию целиком, по частям — не нужно. Части не советовать — фильтр в п. 11 |

## 2026-09-23 — порог по пользователю и протокол сплита (п. 26)

Проблема: аудитория приложения — читающие люди (38–200 оценок у пользователя и друзей).
Профили с 10–19 оценками — не эта аудитория и слабый сигнал, но были и в обучении, и в тесте; тест к
тому же менял состав при каждой правке очистки (случайная перестановка по списку пользователей ядра).

**Итог** (`booksengine exp`, общий тест 17 990 человек, ядро (10, 100) против (20, 100)): NDCG@20 без
изменений — популярность 0.1041/0.1041, ALS 0.2633/0.2635, item-kNN 0.2640/0.2640, ни одно различие не
значимо. Удаление людей с 10–19 оценками не стоит ничего в качестве модели — исходная гипотеза
подтверждена. Ядро: 99.9M → 83.6M оценок (99 879 068 → 83 646 691), 786 570 → 594 967 пользователей,
книги (порог 100) не затронуты.

| вопрос | решение | почему |
|---|---|---|
| `kcore.min_user_ratings` | **20** (было 10) | замер выше: удаление не меняет NDCG ни в одну сторону — сигнал от этих людей был шумом, не полезными данными |
| Отбор теста/валидации | **хэш внешнего id** (`user_id_map.user_id`, `blake2b`) с фиксированным порогом на группу активности, а не случайная перестановка всего пула | порог откалиброван по размеру группы на ядре (20, 100) и не пересчитывается от текущего прогона: тот же человек остаётся в тесте при любой правке очистки |
| Размер теста/валидации на группу активности (20-49, 50-199, 200+) | тест **2000**, валидация **1000** | нужная точность — MDE 0.02 по NDCG@20 (разница мельче для 3b не нужна: сервис для нескольких человек, разница не видна на глаз); худший случай (варианты сравнения не связаны) требует ≤ 2500 в самой шумной группе (20-49); 2000 — с запасом от заниженного до вероятного при парном сравнении |
| Группа 10-19 в `BUCKETS`/отчётах | **убрана** | людей с < 20 оценками в ядре больше нет |

**Где.** `config/cleaning.yaml` (`kcore.min_user_ratings`), `src/booksengine/model/split.py`
(`BUCKETS`, `hash01`, `assign_groups`, `BUCKET_POOL_SIZE`), `tests/test_split.py`.

## 2026-09-23 — этап 2: что и как лежит в PostgreSQL

| вопрос | решение | почему |
|---|---|---|
| Оценки датасета (95M) — в БД? | **не грузить**; обучение читает `data/clean/*.parquet`. Пользователей датасета (683K) — тоже нет | решение пользователя: «сейчас это вообще не нужно». ## 2026-09-23 — архитектура

- **Python — только офлайн** (очистка, обучение, метрики, загрузка каталога и векторов в БД,
  демо этапа 3 как CLI). **C# — онлайн**: схема БД через EF Core-миграции (`dotnet/BooksEngine.Db`),
  позже ASP.NET API с fold-in по готовым векторам. Пользователь сначала спрашивал «может сразу C#?»;
  довод за Python — ML-библиотеки (`implicit`, `scipy.sparse`) и один код для очистки и обучения.
- **Только коллаборативная фильтрация.** Текстовые эмбеддинги описаний как кандидат/гибрид
  предлагались — пользователь отказался: «только CF по ТЗ». Вернуться, когда появятся новые
  источники без истории оценок (холодный старт).
- **`goodreads_interactions.csv`, а не `goodreads_interactions_dedup.json.gz`**: dedup-версия
  (11 ГБ) несёт даты и рецензии, но не помещалась на диск. Следствие — дат нет, временной сплит
  невозможен, holdout per-user.
