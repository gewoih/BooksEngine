## 2026-09-24 — слой вкуса (п. 37): план и правило выбора веса

Пользователь: цель — не цифра NDCG, а чтобы собственные оценки человека заметно влияли на выдачу и модель
находила связи книг по вкусу; голос толпы («все читают») — тоже сигнал, его оставить.

| вопрос | решение | почему |
|---|---|---|
| Направление | **второй слой — модель вкуса на самих оценках толпы** поверх смеси (толпа — кандидаты, вкус — порядок), по шагам 0–3 из `TODO.md`, п. 37, с остановкой на каждом | обе модели смеси учатся только «прочитал»; оценки человека — ручные веса; шанс внутри топ-20 почти плоский (п. 29, 34) |
| Чем судить слой вкуса | **новая метрика «личная точность»** (`booksengine taste-gap`): среди скрытых книг человека — доля пар, где понравившаяся (4–5★) выше непонравившейся (1–3★), среднее по людям | NDCG@20 в основном мерит «прочтёт»: по нему одному вкус получил бы малый вес. Пользователь «не эксперт» — правило выбирает агент |
| Как выбирать вес слоя вкуса | **наибольшая личная точность при двух условиях:** NDCG@20 всех не ниже нынешнего больше чем на шум (парная разница, интервал касается нуля или падение ≤ 0.005) и Low@20 не выше нынешнего | дополняет правило «настройка — по NDCG@20 всех»: NDCG остаётся ограничением, а не целью, для этого одного веса. Выводы — как прежде, по целевым группам |
| Где считать | на Mac пользователя; код — в ветке, агент коммитит | данные и модели только там |

## 2026-09-24 — EASE на 30 000 книг вместо 20 000 (п. 32)

Замер `booksengine ease-size`: книги ранжируются по оценкам в обучении, как в `EASE.fit`.

| вопрос | решение | почему |
|---|---|---|
| Сколько книг в EASE | **30 000** (порог — 411 оценок вместо 636) | все книги профилей из 20–50K лежат до 30K: у `my_ratings` 4 («Роковые яйца», «Горе от ума», «Морфий», «Странник по звёздам»), у `lera_ratings` 3 («Понедельник начинается в субботу», «Цитадель», «Странник»); 40K и 50K не добавляют ни одной. «Гранатовый браслет» (56K) и «Мцыри» (91K) EASE не достать. На тесте в 20–30K — 6.6% входа и 6.2% понравившихся скрытых книг (у 200+ — 7.2% / 6.9%) |
| Память | **одна плотная копия матрицы**: `inv(G.T)` на месте, деление на месте | `scipy.linalg.inv` копировал построчную G, несмотря на `overwrite_a`; `G.T` — та же матрица по столбцам (G симметрична точно), результат побитово тот же. Пик обучения на 30K — 11.8 ГБ, как было на 20K (11.7); 40K — +2.8 ГБ на копию, впритык в 16 ГБ, а профилям ничего не даёт |
| Настройки | прежние: λ = 500, 500 соседей, смесь 50/50 | валидация на 30K: EASE 0.2571 (λ 100 — 0.2492, 2000 — 0.2536; 100 соседей хуже при любом λ), смесь 0.5 — 0.2531 (0.0 — 0.2489, 1.0 — 0.1885); обучение ~190 с на λ |
| Тест, смесь 20K → 30K | NDCG@20 **0.251 → 0.256**, Recall@20 0.275 → 0.282, Low@20 8.6% → 8.6%; 20-49 0.213 → 0.219, 50-199 0.246 → 0.249, 200+ 0.294 → 0.299 (Low 4.3% → 4.2%); coverage 0.076 → 0.085 | прирост во всех группах в одну сторону, но в пределах интервалов (бутстреп по каждой модели отдельно, парного сравнения нет); часть — от скрытых книг 20–30K, которые раньше угадать было нельзя. Шанс: log-loss 0.566 / 0.567, AUC 0.722 / 0.724 — без изменений |
| Выдача на профилях | принята | `my_ratings`: 19 из 20 те же, «Прощай, оружие!» → «Заводной апельсин», у «Зова предков» в объяснении — «Странник по звёздам». `lera_ratings`: 18 из 20, ушли «Три мушкетёра» (держались одним «Монте-Кристо») и «Алиса», пришли «Невыносимая лёгкость бытия» («потому что: … Понедельник начинается в субботу …») и «451°»; шанс ±1 п. п., малоизвестных книг нет |
| Цена | `ease_weights` 10M → 15M строк, загрузка модели в API дольше | приемлемо |
| 40K / 50K | **не сейчас**; вернуться, если у новых профилей заметная часть книг за 30K (`booksengine ease-size` на их CSV), и тогда сначала 40K | профилям не дают ни одной книги; 30–50K — книги с 233–411 оценками, у ALS там 0% выдачи; 50K — 10 ГБ на копию, пик ~18 ГБ при 16 ГБ ОЗУ, ~15 мин на λ, 25M соседей в БД |

## 2026-09-24 — недочитанные во входе EASE (п. 31)

| вопрос | решение | почему |
|---|---|---|
| Вес `dnf` во входе смеси | **EASE — 0 (`mix.DNF_INPUT`), ALS — как 1★** (решение пользователя) | с −2, как у 1★, одна брошенная книга перевешивала профиль: у «Марсианских хроник» вклад «Вина из одуванчиков» −7.86 (z) против +4.33 от остальных 38 книг, весь Брэдбери — на последних местах из 19 967 (шанс 35%), при «451°» на 4★. Вес −1 спасает только «Хроники» (1 352-е место), остальной Брэдбери остаётся на дне; с весом 0 — «Хроники» 62-е (шанс 62%), «Человек в картинках» 245-е (55%). ALS по-прежнему считает книгу негативом («≤ 2»): «не дочитал» — мягкий негатив, причины бывают разные («не то время») |
| Ограничить вклад одной книги | **нет** | задело бы и настоящие 1★ (дочитал и поставил единицу — опустить автора законно); смесь перестала бы быть линейной, а на этом держится точный разбор балла в объяснении |
| Проверка | топ-20 и объяснения на эталонном профиле — без изменений; офлайн-метрики не меняются: в Goodreads нет `dnf` | вес не в `params.json` — отпечаток смеси и `chance.json` прежние, пересчёт не нужен |

## 2026-09-24 — объяснение выдачи и фильтры «уже оценено» (п. 11)

| вопрос | решение | почему |
|---|---|---|
| Как объяснять рекомендацию | **разбор балла смеси на вклады оценённых книг** (`model/explain.py`), не соседи kNN (решение пользователя) | смесь линейна по входу: ALS — Σ w_i·(A⁻¹y_i)·y_j (Hu, Koren, Volinsky 2008), EASE — Σ v_i·B[i, j], z-нормировка — сдвиг и масштаб; сумма вкладов равна баллу до 2·10⁻⁶. kNN — другая модель, объяснял бы не ту выдачу |
| Подпись | «потому что» — до 3 книг с вкладом ≥ 25% от самого большого; «несмотря на» — книга с отрицательным вкладом ≥ 50% от самого большого (2% рекомендаций) | проверка удалением, 400 тестовых, 8000 рекомендаций: без названных книг рекомендация выпадает из топ-20 в 86% случаев (20–49: 89%, 50–199: 90%, 200+: 81%), без стольких же случайных — в 6%, без самых слабых положительных — в 1% |
| «По общему вкусу», когда вклад размазан | **не нужно** | даже когда названные книги дают < 20% положительного балла, без них рекомендация выпадает в 58% случаев — вдесятеро чаще случайных |
| Фильтр «уже оценено по сути» (`model/filters.py`) | тот же основной автор и: тот же ключ названия при неразличимом номере в серии (дубли, пересказы); сборник (`is_collection` или «X / Y»), содержащий название оценённой; часть оценённого сборника | 400 тестовых: срабатывает у 4% людей в топ-20 (200+: 0.07 книги на человека); все 18 срабатываний верные — «1984» при оценённом «Animal Farm / 1984», «Хоббит» при бокс-сете Толкина, бокс-сеты с номером «#1-4, 3.5», пропущенные фильтром серий. На эталонном профиле в топ-40 не срабатывает |
| Место в рейтинге для шанса | считается до фильтра «уже оценено», после исключения входа и начатых серий | так же, как при калибровке шанса |

Выдача на эталонном профиле (37 учтённых оценок; «Рекурсия» и «Граф Аверин» — без id): топ-20 тот же, что у смеси
до п. 11, шанс 80% → 68%, продолжений серий, сборников и книг, похожих на оценённые низко, нет. Объяснения у половины
списка совпадают с тем, что сказал бы человек (Кинг ← «Кладбище домашних животных», «Сияние»; «Дивергент» ←
«Голодные игры»; «Алхимик» ← «Сиддхартха»), у школьной классики США — одна тройка «О мышах и людях, Скотный двор,
1984»: связь через школьную программу, а не содержание. Решение пользователя: оставить, пересмотреть на профилях
друзей (`TODO.md`, п. 33). Этап 3 закрыт.

## 2026-09-23 — основная модель: смесь ALS и EASE 50/50 (п. 24)

EASE^R (λ = 500, 20 000 самых оценённых книг, 500 соседей на книгу — переносимая версия) учится на факте
«прочитал» и оценок не видит. Сам по себе на тесте точнее ALS на треть (NDCG@20 0.254 против 0.192), но
советует больше плохого (Low@20 13.7% против 9.0%), а на эталонном профиле — два Мураками при 2★ и 3★ его книгам,
«Том Сойер», «Сто лет одиночества» (то, что ALS убрал негативным сигналом в п. 8), и четыре Кинга.

| вопрос | решение | почему |
|---|---|---|
| Вход EASE | **взвешен по оценке: 1★ −2, 2★ −1, 3★ 0, 4★ 1, 5★ 2** (решение пользователя) | без веса 1–2★ считаются «понравилось». Валидация, EASE отдельно: все книги с весом 1 — 0.252 / 14.7%, «−1/−1/0/1/2» — 0.243 / 7.5%. Равный вес 1★ и 2★ был переносом правила «≤ 2» из п. 8 без проверки; пользователь: единица сильнее двойки |
| EASE вместо ALS | **нет** | на профиле EASE со взвешенным входом — четыре Кинга, «Сумерки» (только от «Голодных игр» 4★), «Ромео и Джульетта», «Алая буква», «Ночь»: EASE считает «кто читал X, читал и Y» по каждой книге отдельно — сильная пара одной книги поднимает её в топ, а совместное чтение по школьной программе США тянет школьную программу |
| Смесь | **w·z(ALS) + (1 − w)·z(EASE)**, z — нормировка баллов человека по 20 000 книг EASE | ALS держит общий «портрет вкуса», EASE точнее угадывает. Ручная правка списка (совет другой нейросети: «выкинуть „Сумерки“, „Ромео“, „Алую букву“, добавить „Рассказ служанки“, „Кукушку“, „Противостояние“») при w = 0.75 получается правилом сама |
| Вес ALS | **0.5** — выбран по NDCG@20 всех на валидации (правило проекта), подтверждён пользователем | валидация: 0 — 0.242, 0.5 — **0.248**, 0.6 — 0.243, 0.75 — 0.229, 1 — 0.189; Low@20 8.7–9.2% при любом w от 0.5 до 0.8. Парно 0.5 против 0.75: +0.019 NDCG (50–199: +0.016, 200+: +0.031, интервалы не касаются нуля), Low@20 — разница в шуме. На профиле 0.5 против 0.75 — 4 книги из 20: «Алая буква», «Алхимик», «Жребий», «Прощай, оружие!» вместо «Преступления и наказания», «Заводного апельсина», «Уловки-22», «Противостояния». Книг одного автора в топ-20 у типичного пользователя у смеси не больше, чем у ALS (3.5 против 3.7), популярность выдачи та же (медиана 32 тыс. оценок) |
| Книги вне 20 000 EASE *(уточнено 2026-09-24: 30 000, п. 32)* | **не советуются**, процента нет («мало данных») | матрица 101K×101K — 41 ГБ на копию, в 16 ГБ не помещается. Потеря мала: у 99.8% рекомендаций ALS больше 1000 оценок, порог 20 000 — 643. 4 из 37 книг профиля EASE не видит («Роковые яйца», «Горе от ума», «Морфий», «Странник по звёздам») — они доходят до смеси только через ALS |

**Тест** (не участвовал в выборе): NDCG@20 / Low@20

| | все | 20–49 | 50–199 | 200+ |
|---|---|---|---|---|
| ALS (`models/als_neg`) | 0.192 / 9.0% | 0.181 / 18.4% | 0.193 / 10.2% | 0.203 / 5.0% |
| EASE (`models/ease`) | 0.254 / 13.7% | 0.219 / 25.6% | 0.251 / 15.1% | 0.290 / 8.7% |
| **смесь 50/50 (`models/mix`)** | **0.251 / 8.6%** | **0.213 / 18.1%** | **0.246 / 9.9%** | **0.294 / 4.3%** |

Смесь точнее ALS на 27–45% во всех группах и советует плохого не больше. Шанс «понравится» пересчитан для смеси
(`models/mix/chance.json`): различает понравившееся лучше, чем у ALS (AUC 0.72 против 0.71; одно место в рейтинге —
0.64 против 0.58), обещание сбывается с точностью ≤ 3 п.п. в группах 50–199 и 200+ (20–49 — до 7 п.п.). На профиле

## 2026-09-23 — шанс «понравится» в процентах (п. 29)

Пользователь хочет видеть у любой книги, насколько она ему подходит. Процент = **шанс, что книга понравится

пользователя). Смысл — совет, а не приказ: из топа человек выбирает по настроению.

| вопрос | решение | почему |
|---|---|---|
| От чего зависит процент | **место книги в личном рейтинге модели + щедрость человека** (доля его 4–5★, подтянутая к толпе при малом числе оценок: (k + 3·0.73)/(n + 3)); логистическая регрессия, три коэффициента | щедрость объясняет больше места: книга из топ-20 нравится придирчивым (< 50% своих 4–5★) в 54% случаев, щедрым (≥ 90%) — в 93%. Тест (141K скрытых книг): log-loss константа 0.645, только место 0.636, только щедрость 0.589, **оба 0.581**; AUC 0.58 / 0.69 / **0.71** |
| Честен ли процент | **да**: обещание «70–80%» на тесте сбылось в 74%, «90%+» — в 93%; во всех корзинах расхождение ≤ 2 п.п., в группах 50–199 и 200+ — так же | калибровка на валидации, проверка на тесте |
| Какой моделью | **той же, что ранжирует** (с 2026-09-23 — смесь ALS + EASE, `models/mix`) | иначе книга выше в списке могла бы получить меньший процент. kNN различает «понравилось / нет» чуть лучше (0.63 против 0.60), но противоречие в выдаче хуже |
| Что видно на эталонном профиле | 21 из 37 книг на 4–5★ (57%): топ-20 — от 71% до 64%, место 1000 — 54%, последняя книга — 42% | внутри топ-20 процент почти одинаков — это честно: модель не знает, какая из первых двадцати понравится больше. ## 2026-09-23 — гибрид ALS + item-kNN (п. 23): отклонён, основная модель — ALS

Идея: ALS лучше угадывает новые книги, kNN почти не советует плохого (тест, NDCG@20 / Low@20 всех:
0.192 / 9.0% против 0.145 / 2.3%) — взять порядок ALS и отсеять книги по kNN.

| вариант | решение | почему |
|---|---|---|
| Смесь баллов ALS и kNN (вес ALS n₀/(n₀ + n)), переранжирование топа ALS по kNN | **отклонены без замера** | прототип на эталонном профиле (ALS 128, kNN k = 3, β = 50, пул — топ-300 ALS): смесь при n₀ = 50 — четыре Кинга в топ-20 за две четвёрки (на ALS 64 было два), переранжирование — Кинг и бестселлеры. Пул 100 вместо 300 выдачу почти не меняет. Перекос к автору и бестселлерам противоречит цели пользователя (проверенная классика) |
| Вето: книга с отрицательным вкладом kNN (похожа на оценённые ниже своей средней) уходит в конец выдачи ALS | **отклонено** | валидация: NDCG@20 0.189 → 0.170 (50–199: 0.187 → 0.167, 200+: 0.196 → 0.182), Low@20 9.6% → 7.3%. Тот же размен уже даёт сам ALS (негативный сигнал β = 10: 0.171 / 7.1%), отклонённый в п. 8 как слишком дорогой. Из скрытых книг, выброшенных вето из топ-20 ALS, 67% человек оценил на 4–5★ и 8% на 1–2★: «ниже своей средней» ≠ «не понравилось» (та же причина, что у центрирования в п. 8) |
| Строгое вето: только книги — соседи kNN оценённых на 1–2★ | **не берём** | валидация: 0.187 / 8.4% — выигрыш по Low@20 на грани шума; на эталонном профиле топ-20 совпал с ALS, из топ-50 ушёл только «Том Сойер» |

| Тестовые пользователи — в обучении или нет | **исключены из обучения целиком**: 80% их оценок — вход fold-in, 20% скрыты для проверки | реальные пользователи приложения (пользователь и пара друзей) — новые люди, которых нет в обучении; их выдача считается fold-in без переобучения. Мерим этот же путь, иначе метрика завышена. Пользователи Goodreads — «толпа» для обучения и «дублёры» для проверки, не аудитория |
| Что считается попаданием | **градуированно**: скрытая 5★ — выигрыш 2, 4★ — 1, ≤ 3★ — 0; главная метрика — NDCG | 4–5★ — 70% оценок ядра, бинарный порог ≥ 4 не отличает «обожаю» от «сойдёт»; для планирования чтения важно первое. Относительный порог (выше личной средней) отвергнут: у щедрых пользователей почти не остаётся попаданий |
| Дубли произведений (п. 17): сливать при очистке или фильтровать при выдаче | *(отменено 2026-09-23 частично: уверенные тени сливаются при очистке, см. «очистка»)* **фильтр при выдаче** (вариант б): не советовать произведение с тем же ключом «название + основной автор», что у оценённого, если номер в серии не отличается; делается в демо (3c) | замер: 615 теней, 70K оценок — 0.07% ядра, на модель не влияет; эвристика шумная (262 ложных совпадения по номерам серии), слияние по ней испортило бы данные. Дефект виден только в выдаче |
| Выдача ALS на `profiles/my_ratings.csv` (64 координаты, α = 1): Сэлинджер, Фицджеральд, Голдинг, Хаксли, Камю, Кафка, «Преступление и наказание»… | **оценена пользователем положительно**: «многие книги знаю, слышал или планирую прочесть». Известные, «на слуху» книги в выдаче — **не недостаток** | поправка пользователя к анализу агента: 1/10 у «Белых ночей» — «не люблю любовные драмы без сюжета», а не «не люблю Достоевского»; «Преступление и наказание» он сам собирается читать. Низкая оценка — сигнал о книге, не об авторе; разнообразие ценой «известности» (α = 10, п. 21) не нужно |

## 2026-09-23 — этап 2: что и как лежит в PostgreSQL

| вопрос | решение | почему |
|---|---|---|
| Оценки датасета (95M) — в БД? | **не грузить**; обучение читает `data/clean/*.parquet`. Пользователей датасета (683K) — тоже нет | решение пользователя: «сейчас это вообще не нужно». Модель учится из Parquet, API будет работать по готовым векторам/похожестям; «голос толпы» попадает в БД результатом обучения (`work_embeddings`), а не сырыми строками. Экономия ~7 ГБ на почти полном диске |
| Каталог — целиком или только CF-ядро | **целиком** (1.52M произведений, 2.36M изданий) | пользователи ищут и оценивают любые книги, не только 322K ядра; по каталогу же сопоставляется CSV на этапе 3 |
| Поиск по библиотеке | `pg_trgm`, GIN-индексы по `works.title`, `works.original_title`, `editions.title`, `authors.name` | замечание пользователя: по библиотеке будут искать; триграммы находят при опечатках и неполном вводе |
| Оценки приложения | *(отменено 2026-09-24 частично: `value` 1–5, без `scale_max`, см. «шкала только 1–5»)* отдельная `ratings(user_id, work_id, value 1–10, scale_max)` только для `app_users` | с датасетом не пересекается, перезагрузка каталога её не трогает |
| Полки | одна таблица `shelves(user_id, work_id, status)`, статус ∈ to_read / reading / read / dnf | статусы книги у человека взаимоисключающие; пользовательских полок в ТЗ нет (вместо `shelves` + `shelf_items` из плана) |
| Goodreads-id | не ключ каталога: `external_ids(source, entity_type, external_id → internal_id)`; внутренние id выдаются в порядке Goodreads-id | новые источники; одинаковая раскладка id на пустой БД |
| Каталог пропал из новой версии данных, а на него есть оценки/полки приложения | загрузка **падает** (FK `ON DELETE RESTRICT`), БД не меняется | оценки пользователей не теряются молча |
| Автор без имени (2), издание без названия (3) | `authors.name`, `editions.title` — nullable | так в источнике; на этих авторов ссылаются произведения, у изданий есть ISBN. Не выдумываем значения |
| `works.media_type`, `best_edition_title`, `books_count` | не переносятся | `media_type` размечен неверно; `best_edition_title` всегда равен `title`; `books_count` считается по `editions` |

## 2026-09-23 — итоги этапа 1 (ответы на вопросы отчёта)

Понижение веса активных пользователей всё равно делается в моделях этапа 3 (нормализация вклада пользователя в похожесть) — для всех, не только для этих 416 |

## 2026-09-23 — архитектура

- **Python — только офлайн** (очистка, обучение, метрики, загрузка каталога и векторов в БД,
  демо этапа 3 как CLI). **C# — онлайн**: схема БД через EF Core-миграции (`dotnet/BooksEngine.Db`),
  позже ASP.NET API с fold-in по готовым векторам. Пользователь сначала спрашивал «может сразу C#?»;
  довод за Python — ML-библиотеки (`implicit`, `scipy.sparse`) и один код для очистки и обучения.
- **Только коллаборативная фильтрация.** Текстовые эмбеддинги описаний как кандидат/гибрид
  предлагались — пользователь отказался: «только CF по ТЗ». Вернуться, когда появятся новые
  источники без истории оценок (холодный старт).
- **`goodreads_interactions.csv`, а не `goodreads_interactions_dedup.json.gz`**: dedup-версия
  (11 ГБ) несёт даты и рецензии, но не помещалась на диск. Следствие — дат нет, временной сплит
  невозможен, holdout per-user.
