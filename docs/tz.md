## Контекст

Pet-проект: приложение рекомендаций книг для меня и друзей. Главная цель — точный и надёжный механизм рекомендаций, по которому можно реально планировать чтение. UI/UX пока не важен.

Целевой стек: PostgreSQL + pgvector как основная БД, ASP.NET Core для API (позже), Python для офлайн ML-части. Пользователи оценивают книги по шкале 1–10.

На текущем этапе единственный источник данных — датасет UCSD Goodreads Book Graph, он уже скачан. Основа рекомендаций — коллаборативная фильтрация на оценках из этого датасета.

## Задача

### Этап 1. Изучение и очистка датасета

Сначала разберись в структуре данных и составь отчёт: что есть в файлах, как они связаны, объёмы, распределения, качество данных.

Затем максимально очисти датасет от мусора: дубли, битые и неполные записи, некорректные связи между файлами, аномальные пользователи и книги, всё, что будет шумом для рекомендательной модели. Учти, что в датасете есть разделение на издания и произведения: рекомендации и оценки работают на уровне произведения.

Все решения по очистке фиксируй в отчёте с цифрами: что удалено, сколько, почему. Очистка должна быть воспроизводимой одной командой.

После этого этапа остановись и покажи отчёт.

### Этап 2. Каталог в PostgreSQL

Спроектируй схему и загрузи очищенные данные. Учитывай, что позже появятся другие источники данных и пользователи нашего приложения со своими оценками и полками.

### Этап 3. Базовая модель рекомендаций

- Сравни несколько подходов коллаборативной фильтрации, включая простой baseline по популярности.
- Выбери лучший по офлайн-метрикам качества ранжирования на отложенной выборке.
- Реализуй получение рекомендаций для нового пользователя по его оценкам без переобучения модели.
- Учитывай, что вкус человека бывает разнонаправленным, а низкие оценки — это тоже сигнал.
- Сделай демо: я даю свои оценки в CSV, получаю список рекомендаций с объяснением, почему они предложены.

## Правила работы

- После каждого этапа останавливайся, показывай результат и жди подтверждения.
- Решения обосновывай данными.
- При неоднозначностях спрашивай, а не угадывай.
- Датасет только для некоммерческого использования: сырые данные и производные от них не коммитить.
